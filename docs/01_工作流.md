# 工作流

适用：演讲、路演、课程、发布会等由讲者点击推进的 deck。目录见[目录与工程](02_目录与工程.md)，验收见[验收与返修](03_验收与返修.md)。

## 开始时只确认必要输入

目标、受众、放映场景（现场投影／会议共享／录屏），放映电脑与 PowerPoint 版本，内容大纲或讲稿，用户为本份选定的 DESIGN 文件（未选则先请用户从根目录 `DESIGN-*.md` 中选），现有素材。没有的信息标待补，只阻塞真正依赖它的工作。

## 阶段

| 阶段 | 主要产物 | 进入下一步的依据 |
| --- | --- | --- |
| 系列准备 | 环境检查、试放样例、`DESIGN-<风格名>.md`（可多份） | 用户确认静态样页与动态样章 |
| 内容 | 大纲或讲稿：每页要让观众明白什么 | 用户确认内容与顺序 |
| 页面表 | 页序、页型、beat 划分、章归属、风险 | 用户确认划分与页型 |
| 动线剧本 | 每章主角对象的状态链、镜头、每个 beat 的落点 | 用户审一次 |
| 落点关键帧 | 每个 beat 末帧的 Remotion 静帧、原生页样稿、视觉总览 | 用户确认整体风格与关键状态 |
| 动效制作 | 整章渲染、beat 切片、接缝与动态自检 | 同类型对标已确认章；新类型先做样章 |
| 组装 | 构建脚本、pptx、自动播放、结构校验 | 文件能打开、页序与备注正确 |
| 放映验收 | 目标电脑全屏走一遍的记录 | 用户确认 |
| 交付 | 最终 pptx、备份版、源文件 | 用户确认交付内容 |

## 页面表怎么划

先按内容划页，再按“观众这一下要多看懂什么”划 beat。一次点击只推进一个可讲的新状态；讲者需要停下来解释的地方就是一个落点。

每页定一种页型：

| 页型 | 用在 | 不要用在 |
| --- | --- | --- |
| 视频页 | 对象连续变形、镜头推进、状态链、录屏演示 | 现场可能临时改字的内容 |
| 原生页 | 文字密集、表格、图表、需要现场改的内容；简单连续可用平滑切换 | 需要镜头运动或复杂变形的内容 |
| 混合页 | 视频页上叠不动的原生文字（如可编辑的数字、标题） | 叠加元素会与视频里的运动冲突时 |

同一段连续视频页归入一章（C01、C02…），一章对应一个 Remotion 合成。视频页和原生页相接处，或两章相接处，是真正的“切”，要单独设计衔接。

出表后在聊天里主动列出最值得先看的风险：新类型的镜头或变形、需要真实录屏的页、文字过密的页、对放映电脑性能敏感的页。

## 动线剧本与关键帧

确认页面表后，按[动线剧本模板](../templates/动线剧本.template.md)一次写完所有章：主角对象从哪来、每次点击后怎么变、镜头怎样带人看、停在哪里讲。用户审一次后再出关键帧。

关键帧就是每个 beat 的末帧：先在 Remotion 里把各落点状态做出来，用 `npx remotion still` 导出真实静帧；原生页用同一 DESIGN 出样稿。全部汇成一张视觉总览，用户一次确认。静帧确认不等于运动确认。

## 制作

1. 在章合成里实现落点之间的运动；beat 帧号只写在该章的 `beats.json`。
2. 每个 beat 末尾停稳，下一 beat 第一帧保持同一画面，运动从之后开始。
3. 整章渲染 → `tools/split-beats.sh` 切片并检查接缝 → `tools/motion-check.sh` 动态自检。
4. 与对标章连看；新类型先交样章确认，再扩展到其他章。

## 组装与放映

Agent 用宿主的 pptx 能力写构建脚本：原生页按选定的 DESIGN 主题生成，视频页全幅嵌入 mp4，以首帧作为封面，上方叠 `hold-last` 末帧图，演讲者备注写进每页。生成后运行 `tools/pptx-autoplay.py --hold-last`，再做结构校验并在 PowerPoint 中打开检查。最终以目标电脑全屏放映为准。

## 交付

最终 pptx、静态备份版（每页用 beat 末帧替换视频的 pptx 或 PDF）、可选整片 mp4、Remotion 工程与构建脚本、素材来源、QA。满意的章可登记到 `00_系列测试/` 或公共资产，作为今后的对标章。
