# 工具与环境

本仓库是文档工作流加几个脚本，不自带运行环境。首次使用让 Agent 只读检查，缺什么再说明安装目标和验证方式。

| 工作 | 工具 | 换工具时保留的接口 |
| --- | --- | --- |
| 规划、文件与代码 | 能读写本地文件的 Agent | 按任务读规则、写可编辑产物、留证据 |
| 动效 | Remotion（Node.js） | 章合成源码、`beats.json`、渲染命令 |
| 切片、转码、自检 | FFmpeg／FFprobe | `tools/` 脚本与参数 |
| PPT 生成与调整 | 宿主提供的 pptx 能力（如 pptxgenjs）；本地无此能力时在 deck 工程里安装 pptxgenjs | `build_deck.js` |
| 自动播放 | `tools/pptx-autoplay.py`（Python 3 标准库＋ffprobe） | 处理后的 `_auto.pptx` |
| 录屏（按需） | Recordly 或其他录屏工具 | 原始录屏文件与剪辑参数 |
| 放映 | PowerPoint | 目标电脑与版本记录 |

## 检查顺序

1. 记录系统、工作目录、可调用工具和权限。
2. 只读检查（macOS 示例，缺失时记录，不自动安装）：

   ```bash
   node --version; npm --version
   ffmpeg -version | head -1; ffprobe -version | head -1
   python3 --version
   ls /Applications | grep -i -E "powerpoint|keynote|recordly"
   ```

3. 记录本机 Remotion 的实际版本，新 deck 的 `04_动效工程/` 沿用同一版本；尚未安装时，安装方案获批后再装，并记录实际版本。
4. 用一段不含敏感信息的短章完成一次：静帧 → 渲染 → 切片 → 组装 → 自动播放 → PowerPoint 打开。这一步只验证环境，不替代样章。
5. 在**目标放映电脑**上打开 `tools/samples/接缝测试.pptx` 全屏试放：三页应进入即播放、翻页处方块连续不跳。记录 PowerPoint 版本和结果。

## 已知差异与边界

- Remotion 可能全局安装（`remotion --version`），也可能只装在某个工程的 `node_modules` 里；全局找不到时再搜已有工程，不要直接判定未安装。deck 工程内的依赖版本与全局 CLI 保持一致。
- 已实测（Remotion 4.0.532、macOS）：`npx remotion still` → `npx remotion render --codec=h264 --crf=12` → `split-beats.sh` → pptxgenjs 组装 → `pptx-autoplay.py` → PowerPoint 打开并读回自动播放，整条流程走通。
- `pptx-autoplay.py` 写入的是 PowerPoint 的“开始：自动”时间轴，已在 macOS 版 PowerPoint 中读回 `play on entry = true`。
- 已试放：PowerPoint for Mac，`接缝测试.pptx` 全屏放映能自动播放，翻页连续。Windows 版、Keynote、WPS 和网页版 PowerPoint 的实际放映行为需各自试放确认。
- 已试放：同一环境下 `--hold-last` 末帧图机制有效，往前放映无闪，回翻停在末帧。
- 本机 ffmpeg 若没有 `drawtext`（缺 libfreetype），自检图不带时间码，其他功能不受影响。
- 字体：原生页使用的字体需在放映电脑上存在，或在 PowerPoint 中嵌入字体；视频页里的字已渲染成画面，不受影响。
- 工具版本、命令参数会变化，使用前以官方文档为准，不把某次案例参数写成永久规格。
