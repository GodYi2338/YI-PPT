# DESIGN 的建立与校验

`DESIGN-<风格名>.md` 是一种风格的视觉与运动规范，放在系列根目录；本仓库只带模板和一份通用示例（[examples/DESIGN-apple-style.md](../examples/DESIGN-apple-style.md)），使用者自己建立或复制到根目录后才算数。一个系列可以有多份，没有默认的 `DESIGN.md`。每份 deck 由用户选定一份并记入页面表，Remotion 工程和 PPT 主题的取值都以选定的那份为准。格式参考 [google-labs-code/design.md](https://github.com/google-labs-code/design.md)：JSON front matter 放参数，正文解释用途；`x-deck` 是本仓库的扩展。

## 从测试到正式规范

按[设计提示词](../prompts/02_建立DESIGN.md)三步走：

1. **静态样页**：用同一段中性内容做少量有实质区别的真实画面方案，同时包含一张视频页落点和一张原生页，比较背景、字体、层级、图形。
2. **动态样章**：在选定的静态方案上做一段 3～5 个 beat 的样章，覆盖对象变形、镜头推进和停稳，切片后组装成 pptx 实际放映。
3. **写入规范**：从确认的样本提取参数，按[模板](../templates/DESIGN.template.md)写入根目录 `DESIGN-<风格名>.md`（风格名由用户定），记录样本路径和确认范围。

Agent 从确认样本填参数，不让用户逐格设计 JSON；用户只判断真实画面与运动，并确认采用范围。没验证过的参数保持待定，不补成默认值。

## 两端共用

- **Remotion**：`04_动效工程/src/design.ts` 的取值以选定的 DESIGN 文件为准，不手抄第二份数值。
- **PPT**：原生页的主题颜色、标题／正文字体、页脚与版式取自同一 DESIGN；视频页与原生页相邻时，背景、字号和主色要对得上。

## 校验分三层

- **结构**：front matter 可解析，引用存在，颜色与单位有效，当前用到的 token 都有值。
- **实现**：Remotion 组件与 PPT 版式实际用了这些值；缺字体时的回退检查过。
- **视觉**：真实静帧和放映过的样章能证明构图、可读性、运动因果与停稳。结构通过不代替后两层。

已有规范只沿用已确认的范围；改动只改这次确认覆盖的内容，先保留原版。
