# 验收与返修

## 哪个文件决定什么

| 事实 | 唯一记录位置 |
| --- | --- |
| 内容与页序 | 用户确认的大纲或讲稿、页面表 |
| 采用的设计、素材、渲染版本，制作进度 | 页面表 |
| 正式可编辑实现 | Remotion 工程与 `build_deck.js` |
| 检查结论、问题与用户原话 | QA 表 |

新文件不是自动采用的版本，“允许制作”也不是“验收通过”。QA 栏只用：通过、未通过、未验证、不适用（原因）。结论绑定文件版本和范围。

## 三个验收节点

### 样章：只给新类型做

与已确认样章同类型（同一视觉系统、同类对象演化与镜头方式）的章不做样章：动线剧本写明对标章，做完后连看，状态变化的持续性、主体可读尺度和镜头推进不能明显低于它。尚无确认范例的镜头、空间、变形、转场或技术路线属于新类型，出页面表时就提醒用户，先做一段覆盖难点的样章，确认后登记为范例。

### 视觉总览：确认落点

全部关键帧（beat 末帧）和原生页样稿汇成一张总览。检查：每个落点是否可讲、主体是否够大、文字是否在投影距离上读得清、相邻落点之间的变化是否清楚、原生页与视频页风格是否一致。静帧确认不覆盖运动。

### 放映验收：在目标电脑上

- 用最终 `_auto.pptx` 在目标电脑（或同配置电脑）全屏、用翻页笔或键盘从头走到尾。
- 每页：进入即自动播放、无黑闪或封面跳变、播完停在末帧、视频页之间翻页无跳动。
- 回翻、跳页、从当前页开始放映时的表现符合预期（回翻应停在该页末帧，再往后翻接上下一页；跳页从头播放）。
- 动效流畅不掉帧；文字在实际投影或共享画面上读得清。
- 演讲者备注齐全；文件大小可以接受；字体在目标电脑上可用（原生页）。
- 备份版（静态 pptx 或 PDF）能打开，页序一致。

没在目标电脑放映过的项目写“未验证”，不能用“本机打开正常”代替。

## 四种画面检查

- **删字测试**：去掉解释性标题后，主体关系仍然可见。
- **静音讲述测试**：不看备注、只看画面，能看出对象、变化与因果。
- **讲述合拍测试**：按讲稿边讲边点，动效时长不让讲者干等，落点停稳后有内容可讲。
- **对标测试**：与对标章连看，不明显低于它。

Agent 不能以正常速度观看时，交用户前先跑[动态自检](../tools/README.md)，修掉长时间无用途的停留、一闪而过的过程和空白画面。它只定位，不替代用户 1× 观看。

## 返修只重查受影响内容

收到用户意见时，按原话记入 QA（“用户原话：……”），不改写成规则语言。改动前写清“本轮修改、必须保持、完成后复查”。

| 变化 | 重新检查 |
| --- | --- |
| 某个 beat 内的动效 | 该 beat；首尾帧变化时复查前后接缝 |
| beat 帧号或时长 | 重新切片、整章接缝、受影响页的封面帧 |
| 落点画面 | 该 beat 和下一 beat 的首帧、关键帧总览中的对应格 |
| 原生页内容 | 该页；与视频页相接时复查衔接 |
| 页序 | 构建脚本、跨页衔接、备注 |
| 仅备注或文件名 | 备注／路径，可沿用原检查结论 |

更新采用版本后，相关 QA 改为未验证，复查后再填结论。整份交付后，页面表只留当前状态、采用版本和未决事项，旧补记移入 `90_历史/`。
